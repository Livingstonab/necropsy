Resurrect in Kiro

NECROPSY exposes its pipeline to Kiro over the Model Context Protocol.

1. Register the MCP server

Add this to .kiro/settings/mcp.json in your workspace, or ~/.kiro/settings/mcp.json for every workspace.

{
  "mcpServers": {
    "necropsy": {
      "command": "python",
      "args": ["-m", "necropsy.cli", "mcp"],
      "env": { "DATABASE_PATH": "./necropsy.db" },
      "disabled": false,
      "autoApprove": ["list_graveyard", "get_exhibit"]
    }
  }
}

2. Ask Kiro to revive a repo

Reconnect the server from Kiro's MCP panel, then say:

“Analyze github.com/owner/dead-repo with NECROPSY, then write a revival spec.”

Kiro calls analyze_repo, receives the structured post-mortem, and writes a revival spec mapping each plan step to a concrete task. The four tools: analyze_repo, get_exhibit, list_graveyard, write_revival_spec.

3. What it will and will not do

NECROPSY reads the GitHub REST API and nothing else. It never clones, never executes repository code, never opens issues, and writes nothing back except its own cache. “Analyze this repo” is the whole contract.
